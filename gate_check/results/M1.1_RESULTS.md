## The four acceptance tests

| test | test one (3P) | test two (2P) |
|---|---|---|
| 1. relative band non-empty | **PASS** 0.0051–0.3582 S | **PASS** 0.016–~5–9 S |
| 2. profile smooth, flag carried | nothing flagged — **but see the caveat** | node 5 flagged correctly |
| 3. upper crossing located | **PASS** between 0.3582 and 0.4509 S | **PASS** between 5.06 and 9.00 S |
| 4. truth inside the absolute band | **PASS** 0.2063 S inside | **PASS** 0.6856 S inside |

**The caveat on test 2, which matters.** The smoothness test as I wrote it fires
when a node sits *above* a chord through its neighbours. On a convex rising limb
every node sits *below* one, so the test cannot fire there however badly the
refits stall. It catches **spikes** — it fired correctly on 2P's node 5 and on
the known 3S stall — and is blind to systematic over-estimation along a limb.
3P's "nothing flagged" is therefore weak evidence, not a clean pass. A
curvature-based test is needed before this is an acceptance criterion.

## lambda2: weak smoothing wins, keep it

Winning solves on 3P, over 11 nodes with a finite result:

| winner | nodes |
|---|---|
| `warm_fwd@l2=0.01` | **6** |
| `warm_fwd@l2=0.1` | 3 |
| `warm_bwd@l2=0.1` | 1 |
| `warm_bwd_seed@l2=10` | 1 |
| **l2 = 1** | **0** |

**lambda2 = 0.01 supplies the winning solve at more than half the nodes and
lambda2 = 1 supplies none.** Dropping 0.01 from the release set would have
reintroduced the stall. It is also the dearest and least stable setting
(2.8 min a solve against 57 s at lambda2 = 1), so it costs what it is worth.

The MAP-at-lambda2=1 column sits consistently above min chi2 — 25.090 against
25.753 at node 5 — so the min-chi2 definition changes the answer, not just the
bookkeeping.

**Sweep direction is column-dependent**: forward won 9 of 11 on 3P, backward won
6 of 11 on 2P. Both sweeps stay.

## chiref: the unconstrained solve is not the minimum, on both columns

| column | unconstrained multi-start | min over constrained nodes | gap |
|---|---|---|---|
| 3P | 25.3744 | 25.0891 | **+0.285** |
| 2P | 28.4587 | 27.1749 | **+1.284** |

Two columns of two, same direction, so this is a property of the solver rather
than a quirk of one dataset. On 3P all three unconstrained starts returned
25.374 and 39.468; on 2P all three returned 28.459 to three decimals — so
multi-starting the unconstrained solve does not cure it.

Under `chiref = min(unconstrained, min over constrained nodes)` the relative
thresholds become **28.93 on 3P** (from 29.21) and **31.01 on 2P** (from 32.30).
3P's relative band tightens to 0.0051–0.2845 S; truth at 0.2063 S stays inside.
